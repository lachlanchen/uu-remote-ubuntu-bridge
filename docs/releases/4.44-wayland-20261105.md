# UU 4.44 on the 7090 Wayland workstation

## Installed state

On 5 November 2026 this workstation pulled main through `a6b0416`, refreshed
the bridge helpers and moved from UU 4.42.1.2835 to the exact reviewed
4.44.1.3978 bundle. It uses Ubuntu 24.04, GNOME 46 Wayland, Wine 11 and the
pinned FreeRDP relay to the existing physical desktop. The relay is 1920x1080.

The cursor guard is enabled persistently with `UURB_CURSOR_GUARD=on` and
`UURB_CURSOR_SIZE=auto` in `~/.config/uu-remote-bridge/environment`. On this
desktop the relay cursor resolves to 24x24. Existing audio-off, keyboard,
clipboard, networking, saved login and desktop-target settings were preserved.
The service is enabled and user lingering is enabled. No OS reboot or GNOME
logout was performed, so reboot behavior was not tested in this run.

The official download endpoint's HEAD response advertised 4.46.0.4716 during
this work. That release has no reviewed manifest in this checkout and was
**not installed**. This deployment uses the newest reviewed bundle, not a
claim that 4.44 is the newest vendor release. Automatic promotion remains off;
the manifest still has no fleet-wide `acceptance` record.

## Cursor startup failure and fix

The first production-path switch automatically returned to 4.42 after the
relay's cursor readiness marker disappeared. Its log contained the hidden
cursor message followed by a fragment of the startup line. The guard's
initializer and the UI thread both call `write_log()` using one append handle.
Under Wine 11, concurrent `WriteFile()` calls on this handle can overwrite
each other's records. The launcher consequently rejected a running guard.

`src/uu_cursor_guard.c` now serializes writes using an SRW lock. The readiness
check is unchanged; no extra timeout or false success condition was added.
The opt-in guard remains process-scoped, with no authentication changes.

`tests/probes/uu_cursor_log_probe.c` includes the production implementation
and starts eight writers, each emitting 2,000 records. Before the fix, the
reproducer retained only 201 ready and 936 hidden-cursor messages, plus 1,359
malformed lines. After the fix, all 8,000 messages of each kind survived with
zero malformed lines. Run the isolated regression with:

```bash
scripts/test-cursor-log.sh
```

It creates its own temporary Wine prefix and Xvfb display, never injects into
the real application, and removes successful test artifacts. MinGW, Xvfb,
`xvfb-run`, `xauth`, and the supported Wine installation are required.

## Deployment and rollback

The vendor installer ran against a stopped copy of the prefix with networking
disabled. Existing account registry and cache hashes were compared before
first launch. The installer added one new version-specific log; it was moved
to private evidence before repeating the strict comparison. Existing account
files were not excluded or rewritten. Login survived the switch.

Candidate service overrides use **`UURB_WINEPREFIX`**. Prefix-only installation
and verification use **`WINEPREFIX`**. These are distinct interfaces; setting
only `WINEPREFIX` on the service does not select a candidate. After testing,
the old and new prefixes were renamed on the same filesystem, and prefix-only
installation refreshed helper paths without reconfiguring GNOME RDP.

The failed first switch demonstrated automatic rollback. After the logger fix,
three candidate cold starts and the production start passed. A rollback timer
protected the deployment until the production/controller checks completed.
The candidate override and timer were removed after local acceptance.

Private workstation recovery state is retained at:

```text
~/.local/state/uu-upgrade-20261105/previous-4.42-prefix/
~/.local/state/uu-upgrade-20261105/runtime-442/
~/.local/state/uu-upgrade-20261105/environment.before
~/.local/state/uu-upgrade-20261105/rollback-4.42.sh
```

To return this workstation to the retained 4.42 prefix, run the following
locally or over an independent SSH connection. It disconnects UU, preserves
the newer prefix separately, and leaves the physical desktop logged in:

```bash
bash ~/.local/state/uu-upgrade-20261105/rollback-4.42.sh
```

The script checks the retained server against its own manifest before stopping
UU. It is single-use because the retained prefix moves back into place. It has
been syntax-checked but was not executed after final acceptance. The earlier
automatic rollback was exercised successfully. Prefixes, credentials, raw
screenshots and private test evidence must not be committed to Git.

## Validation and limits

- Compatibility helpers built with warnings treated as errors.
- Python suite: 262 tests, 261 passed and one optional skip.
- Concurrent cursor logger: 16,000 complete records, no corruption.
- Three repaired candidate starts passed all quick verifier checks.
- Production verifier: exact patched binary, current helper digest, live IPC,
  cursor guards, relay, native terminal handoff and saved account state passed.
- One server PID remained stable for 270 seconds, with zero GNOME RDP file
  descriptor growth over that interval.
- An authenticated Mac UU controller viewed the current physical desktop,
  clicked the scratch test button, typed English, pasted exact multiline
  English/Chinese text and typed again after disconnect/reconnect.
- Cursor pixel checks found a nontransparent 24x24 cursor and confirmed that
  its coordinates changed after remote mouse movement. The server reader
  guard's visibility/bitmap self-test also passed.
- The installed PowerShell shim reached the native Linux PTY and returned the
  expected marker, Linux identity and exit status zero.
- Isolated text tests passed Chinese, emoji, multiline text, composition
  revisions and a complete 2,000-record batch without losing prior text.

The Mac test used VNC only to drive the native Mac UU controller; input into
Ubuntu went through UU and its FreeRDP relay. This does not establish new
end-to-end phone dictation, every IME, Ubuntu-to-Mac automatic clipboard,
file-transfer or AMD hardware acceptance. Those remain separate checks.
