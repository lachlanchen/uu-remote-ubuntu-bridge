# UU 4.44.1.3978 compatibility review

This manifest adds exact-hash support for the official Windows build
4.44.1.3978. Static patch approval is separate from unattended promotion:
the manifest has no automatic-promotion acceptance record.

## Release identity

The official release endpoint returned different builds for HEAD and GET on
26 October 2026. HEAD advertised 4.44.1.3978 while GET still redirected to
4.44.0.3919. The newer file was downloaded directly from the official CDN URL
recorded in the manifest. Its extracted server and desktop client both report
4.44.1.3978 in their PE version resources.

## Patch review

PE exception records bound the reviewed functions. File offsets below belong
only to the server hash above; the patcher rejects other binaries.

| File offset | Function RVA range | Reviewed behavior |
| --- | --- | --- |
| `0x5dccb0` | `0x5dd530..0x5ddc54` | The constructor stores its virtual-input argument at object offset `0x268`. The same field is passed to the `virtual switch state:` diagnostic. Replace only the argument load with zero. |
| `0x5b1cb2` | `0x5b2750..0x5b28d8` | The reader references the UTF-16 `global` / `virtual_mouse_switch` setting and returns `value == 2`. Force the returned Boolean false. |
| `0x5b1d64` | `0x5b2940..0x5b2b6d` | The setter references that same setting, receives its Boolean in `dl`, and stores `sil` through the setting object. Force that value false. |

The short masked setter pattern has four candidates. Only `0x5b1d64` matches
the full previous instruction sequence and the virtual-mouse setting
references. The other three matches are not patched.

The SendInput factory is at RVA `0xdc5010`, with its callback at `0xdca720`.
The callback checks for a nonzero UINT-sized event count and tail-calls the
imported SendInput function with `sizeof(INPUT) = 40`. The backend selector
at `0xdca7a0` retains the explicit false branch that releases the VHID path.
The bridge changes none of those backend functions or authentication logic.

The driver helper has the same audited hash as 4.42. The installer and
verifier recognize this release for reversible driver-helper suppression,
structured startup logs, and exact-version/nonce IPC readiness. Existing
releases, default installer selection, input routing and clipboard semantics
remain unchanged.

## Validation scope

Static review used the repository audit tool, PE section/exception/resource
inspection and bounded `objdump` disassembly. Applying and verifying the patch
on a disposable server copy succeeded; restoration reproduced the original
SHA-256 exactly.

The Ubuntu 24.04 X11 test host uses Wine 11, a loopback VNC relay to its existing
desktop, and direct X11 input. The following checks passed:

- Compatibility helpers compiled with warnings treated as errors.
- The Python suite ran 262 tests: 260 passed and two optional checks skipped.
  The final run used a private network namespace to avoid host-port contention
  in the real TigerVNC window tests. The host's viewer was not replaced.
- Physical/phone input fixtures delivered all 52 expected transitions and a
  2,000-record batch without loss.
- Text fixtures covered Chinese, punctuation, emoji, multiline text and
  dictation revisions that preserve earlier committed text. A 2,000-character
  input produced one complete paste.
- Mouse fixtures verified coordinates and all six tested transitions.
- Clipboard fixtures verified Wine-to-X11 owner filtering, initial-content
  suppression and bounded helper cleanup. These do not certify every mobile
  client's bidirectional clipboard behavior.
- The native terminal fixture verified an authenticated Ubuntu PTY, Unicode
  output and a 24×80 resize. The vendor updater guard blocked `Upgrade.exe`
  while allowing ordinary Wine execution.
- The installed candidate passed exact binary, IPC, helper, canvas-size and
  desktop-relay checks, and retained one server process for 270 seconds.

The production-path start also passed the same readiness checks. UU's own
`status` command reported `appVersion: 4.44.1.3978`, `isLoggedIn: true`,
`serviceStatus: running`, `networkStatus: connected` and `lastError: null`.

These are local fixture and host-runtime results. A new end-to-end mobile
controller, rapid typing, Chinese dictation, reconnect and bidirectional
clipboard acceptance report is still required before enabling unattended
promotion on other installations. Neither Wayland nor a FreeRDP relay was
qualified by this run. The manifest deliberately has no `acceptance` object,
and the fresh-install default remains unchanged.

## Readiness format change

In this build, `uuyc-cli.exe version` returns several named fields instead of
the bare version expected by older checks. It can report its own version even
when the main application is absent. The global `--version` option still
returns the exact CLI version.

The live `echo` response changed from the bare nonce to `echo: <nonce>`.
The verifier now selects both formats by the exact audited release. It still
requires the expected version **and** an exact nonce response from the running
application. Wrong versions, missing IPC, stale replies and an unformatted
reply for 4.44.1 are rejected. Older releases retain their previous checks.

The first live candidate was returned to the previous version because the old
checker rejected these new reply formats. After the version-specific fix,
readiness passed without changing authentication or input behavior.

## Account preservation and deployment

The installer ran without network access against a stopped-prefix copy. The
existing production prefix was preserved separately. Before the candidate's
first launch, the login registry digest and user cache matched the original.
The installer added one version-specific log beneath the shared state tree;
that new log was moved to private upgrade evidence before the strict state
comparison. Existing account files were not excluded from the comparison or
rewritten. The comparison then passed.

The candidate was tested using a temporary service override and an automatic
return timer. Once its local runtime checks passed, it was moved into the normal
prefix location and its compatibility helpers refreshed. Only UU's service
was stopped and started. Its saved desktop, keyboard, clipboard, audio and
network settings were preserved; GNOME RDP settings were not reapplied. The
independent RDP and RealVNC service processes stayed unchanged.

The old prefix and helper copies remain in private storage for rollback.
Existing service enablement and user lingering remain enabled; no operating
system reboot or desktop logout was performed. Boot persistence is checked
from the installed units and settings, not claimed as a tested reboot.
