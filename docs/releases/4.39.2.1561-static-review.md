# UU Remote 4.39.2.1561 static and canary review

This note records privacy-safe evidence for the current official UU Remote
`4.39.2.1561` compatibility patch. It is not a live-promotion acceptance
record. Proprietary binaries, raw logs, account state, device identifiers,
tokens, screenshots, and host-specific paths remain outside the repository.

## Semantic continuity from 4.39.1

The server and health-monitor binaries changed from `4.39.1.1375`, so the old
manifest was not reused by version assumption. All three complete original
signatures nevertheless remain unique in the new server, and the relevant
semantic strings are unchanged:

- `gvinput_open result=failed fallback=send_input`
- `gvinput_send result=degraded reason=driver_injection_failed fallback=send_input`
- `gvinput_send result=failed fallback=send_input code=`
- `virtual switch state:`

PE exception-function boundaries were re-derived for every candidate. Each
enclosing function has the same byte length as its 4.39.1 counterpart, and the
normalized instruction/control-flow sequence is identical. Only relocated
addresses and displacements differ. The reviewed patch therefore applies the
same three behavior-limited edits at newly derived offsets:

| File offset | Behavior |
| --- | --- |
| `0x5addd6` | Force the constructor's virtual-input argument to false |
| `0x597612` | Force the persisted-setting result to false |
| `0x5976c4` | Force the runtime setter's saved Boolean to false |

Patch, full-hash verification, and byte-identical restore all passed on a
disposable copy.

## Disposable-prefix and cold-start results

A cleanly stopped, signed-in `4.33.0.8907` prefix was copied before the test.
The official 4.39.2 installer and reviewed patch were applied only to that
copy. The login-registry digest and all account-bearing user/shared caches
remained byte-identical across the in-place update.

The copied prefix completed a genuinely stopped 300-second canary run through
the normal bridge, native VNC desktop relay, direct-X11 input broker, and the
existing XRDP desktop. The 4.39.2 CLI responded throughout; the service stayed
alive and used no swap. Production 4.33 was restored afterward without
restarting or changing XRDP.

As in 4.39.1, this release writes its server log in binary `.slog` form. A
separate Windows UU CLI accepted guarded connect/disconnect requests, but no
visible controller session opened and the canary broker received no controller
events. This is not treated as controller-input or reconnect acceptance.

The manifest deliberately has no `acceptance` object. Live promotion remains
closed until one real controller session proves mouse, keyboard, mobile
IME/dictation, CJK, symbols, shortcuts, clipboard, native terminal,
disconnect/reconnect, and service restart behavior against this exact binary.

## Operator-authorized workstation switch

After the disposable-prefix canary, the workstation owner explicitly requested
a live switch to this exact release. A full stopped-prefix rollback copy was
created first. The live install preserved the login-registry digest and usable
account state, completed another 300-second canary plus a 90-second post-swap
check, and left XRDP running with the same main process. UU's normal first-run
creation of a versioned configuration cache was accepted only after confirming
that it contained no account-state loss.

This local switch does not manufacture a reusable release acceptance. The
manifest remains fail-closed for unattended promotion until a real controller
completes the input and reconnect checklist above.
