covered by `patches/uu-remote-4.42.1.2835.json`. Its SHA-256 is
`d3a7776f6fb00b196e2fcbf8acba06fd52b19437b0da80fec0ae838ee362f06f`.
The official endpoint currently calls it `uuyc_4.42.0.exe`; the bundled CLI

The installed patched server hash is
`3bcd664ad1b5b776b8e3f28276123bc3c7ac40464a19879dfc7aaa0f804706e5`.

This is an operator-requested update on an X11/VNC/direct-input host. During
this work, upstream independently published its [Wayland/RDP acceptance](4.42.1.2835-acceptance.md)
at `6c396f6`. That metadata was incorporated after verifying that the runtime
source files and binary identities were unchanged. Keep the two hosts' input
routes and test evidence distinct; neither record claims every client works.

## What the outage evidence established

The old service had accumulated 30 restarts. Recent journal entries included
critical-child exits and a preferred network-interface change. By inspection
time it had restarted: local IPC, the existing desktop relay and input hooks
were working. Its live executable still matched the patched 4.39 manifest.
There was **no evidence of an unpatched vendor replacement on this host**.
The records do not establish one exclusive cause for every earlier outage;
an active systemd unit alone is not a remote-connectivity test.

A real upgrade failure was reproduced: `install.sh` unconditionally fetched
a pinned Windows FreeRDP nightly that now returns HTTP 404, even on VNC-only
hosts. The runtime transaction rolled back. The fix builds/installs FreeRDP
and libei only when the selected relay is RDP; the launcher likewise requires
libei only on that route. Existing RDP files are retained, not deleted.
A regression executes that preparation boundary with failing download stubs.

## Upgrade procedure used

1. Fast-forward the clean main checkout and inspect the upstream compatibility
   and rollback notes. Record the active desktop route and independent RDP/VNC
   service identities.
2. Refresh current bridge helpers with the guarded runtime-only operation.
   Preserve the saved physical desktop, direct-X11 keyboard route, phone-text
   `auto` mode, timing and audio-isolation drop-in.
3. Temporarily stop the existing maintenance timers during the transaction.
   Stop only UU and its prefix, then copy the complete signed-in prefix. Resume
   the original service while preparing the separate candidate.
4. Run the exact-hash installer and reviewed patches against the candidate in
   a networkless Bubblewrap namespace. Bind only the candidate and build output
   writable, and set the working directory **inside the writable candidate**.
   A read-only inherited working directory caused installer extraction to fail;
   changing the sandbox working directory corrected it without broadening the
   filesystem writes or network access.
5. Require exact equality of the login registry digest and account-bearing
   user/shared caches before starting the candidate. Those checks passed.
6. Arm a timed return to the original, select the candidate through a runtime
   service override, and run the live verifier plus a 270-second stability
   gate. The user confirmed connection, controls and Chinese input through UU.
7. Stop only UU, retain the original complete prefix, move the tested candidate
   to the normal prefix path, reinstall the helpers for the normal path, remove
   the temporary override, and restart. Cancel the timed return only after the
   normal-path verifier succeeds.

The original prefix, runtime files, configuration, tests and private rollback
helper stay in a mode-0700 local state directory. No proprietary binaries,
account state, raw desktop screenshots or private device identifiers are in
Git. A prefix copy was approximately 32 GiB; check free space first.

## Input and clipboard checks

The isolated tests passed for fast text, exact 2,000-record input, Chinese,
smart punctuation, emoji, multiline dictation, mixed-language revisions that
preserve an earlier message, the mouse helper, the authenticated Linux PTY,
and blocking the unmanaged vendor updater. The existing inbound clipboard
fixture passed its startup, owner-filter, Unicode, timeout and cleanup tests.

The optional [host clipboard return](../semantic-text-and-clipboard.md) was
enabled on this X11/VNC host. Its separate fixture proves exact multiline
Chinese/emoji in Wine's CF_UNICODETEXT, not merely the private X selection.
It rejects bridge-owned dictation/incoming selections, does not replay startup
content, and never injects a paste. It supports text up to 60 KiB; image/file
clipboard transfer is not a claimed feature.

The source suite completed 175 tests (173 passed, two optional tests skipped);
the isolated X11/Wine clipboard and disposable systemd recovery tests were run
separately. Source tests do not prove every phone or remote-client behavior.
The user confirmed real controls/Chinese during the candidate test; keep a
separate record of real clipboard-in-both-directions confirmation.

## Persistence and boundaries

The UU bridge, shared physical VNC and keyring startup units remain enabled;
the user manager has lingering enabled. `Restart=always`, prefix-scoped
cleanup and the existing resource limits remain in effect. RDP and RealVNC
kept their original PIDs and active states throughout the update. Open desktop
applications were not logged out or restarted. No machine reboot was performed,
so boot behavior is configuration-verified rather than a new reboot test.

Automatic promotion remains off: future unreviewed Windows installers must
not replace the patched runtime. The source's process-local `upgrade.exe=d`
guard is now installed. A normal failed service is recoverable through
systemd; an external network outage or expired account still needs diagnosis.
