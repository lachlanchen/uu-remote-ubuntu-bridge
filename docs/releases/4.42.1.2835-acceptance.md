# UU 4.42.1.2835 workstation acceptance

Date: 1 October 2026. This follows the withdrawn first canary in the
[static review](4.42.1.2835-static-review.md), not a reinterpretation of that
incomplete test. The operator explicitly requested testing and switching.

## Scope and identity

Test host: Intel x86-64, Ubuntu 24.04, GNOME 46 physical Wayland desktop,
1920x1080 private Wine/RDP relay. Controller: native macOS UU 4.42.0 (625),
driven through authenticated Mac Screen Sharing. This is not ARM acceptance.
The installer/server hashes are bound in the manifest; its packaged CLI
reports 4.42.0.2770, as documented in the static review.

The disposable prefix was refreshed from committed bridge source `982e277`
with `install.sh --prefix-only --skip-packages --skip-account-login --no-start`
and the exact 4.42 manifest. A temporary service override selected only this
prefix; a timed return to the untouched production prefix protected testing.

## Observed checks

- Exact runtime source digest, patched server hash, fresh nonce IPC echo,
  version, input hooks, authenticated native PTY bridge, and GNOME relay checks
  passed. One server PID survived 270 seconds with zero GRD descriptor growth.
- The native Mac UU client displayed the existing physical desktop, without
  a second Linux login or desktop. A dedicated Wayland GTK editor captured
  only its own test input; no global keystroke recording was used.
- Mouse movement changed the intended focused widget. Separate button press,
  release, and click counters advanced together. English letters, numbers,
  spaces, shifted punctuation and capitals matched the sent string exactly.
- A fresh Mac clipboard update followed by Ctrl+V delivered exact multiline
  English/Chinese text. The test saved all original Mac pasteboard items/types
  privately for restoration, not just its plain-text representation.
- Disconnecting only this test device and reconnecting restored video and
  delivered a new exact marker to the same editor.
- Restarting the complete bridge service produced a new server PID, passed
  verification again, and allowed a new controller connection. A second
  English marker, mouse button click, and Chinese paste worked after restart.
- No UU login prompt appeared during connection/reconnection/restart. The
  original staging install preserved the stopped-prefix login records. The
  registry login digest still matched the checkpoint after live testing;
  normal runtime setting/cache changes are not claimed byte-identical.
- The installed PowerShell shim returned an exact marker, Linux identity,
  and exit zero through the native Ubuntu PTY. This tests the installed shim,
  not the complete vendor remote-terminal UI.
- Isolated semantic-text regressions passed Chinese, punctuation, emoji,
  interleaved composition edits, preservation of earlier text, multiline text,
  and 2,000-record delivery. This does not substitute for a real phone test.

## Lessons from the controller harness

Two test assumptions initially produced misleading failures. Back-to-back
synthetic mouse down/up was too brief across nested remote transports; held
press/release made actual clicks observable. The Mac client also sent relative
movement after capture. Screen coordinates in the outer VNC image were not
absolute coordinates in the inner Ubuntu session. Track the private relay
cursor and confirm the actual widget/counter instead of repeatedly clicking
an assumed pixel or typing into an unknown application. No input routing or
binary patch was changed to conceal those test problems.

Before typing, inspect a fresh screenshot and use a dedicated scratch window.
Stop if it is absent. Do not send test text into a user's terminal, overview,
or active project. A successful SendInput return alone is not acceptance.

The isolated terminal test now also points `WAYLAND_DISPLAY` at a nonexistent
socket. Clearing `DISPLAY` alone did not prevent newer Wine from showing its
temporary prefix-configuration window on the physical Wayland desktop. This
test-only change leaves the production Wine environment unchanged.

## Promotion and rollback

The manifest now contains the five required acceptance flags and exact
installer/patched-server hashes. Use `scripts/promote-approved-release.py`,
not a prefix rename or a relaxed verifier. It requires a clean pinned commit,
complete evidence, an already healthy live runtime, enough disk space, a full
stopped-prefix snapshot, strict login preservation before first launch, and
another 270-second verification. Failure restores the previous prefix.

The source tag `uu-4.40.1.2090-working-20261001` remains unchanged. The complete
private 4.40 checkpoint and its verified restore helper remain available as
documented in the static review. Neither credentials nor proprietary binaries
are committed. The canary override and timer must be removed before normal
production operation. Automatic updater/repair timers remain disabled on this
workstation; acceptance does not turn them on.

## Limits

No machine reboot was performed. Real mobile IME/continuous dictation, file
transfer, and the vendor remote-terminal UI are not covered by this controller
run. The additional clipboard companion is deliberately controller-to-host
text only; the existing RDP/UU clipboard path carries the reverse direction
verified below. Existing isolated tests cover
the semantic and terminal mechanisms, not every remote device or workflow.
There is no ARM, AMD GPU, or all-hardware guarantee. Keep the previous runtime
until normal daily use has also been confirmed.
